# 训练、恢复与滚动计划

仅在用户报告训练、询问训练计划/恢复/部位图或配置训练提醒时读取。普通饮食记录不要读取。

## 适用边界

面向 18 岁以上普通成年人的一般性力量与有氧记录。不能诊断伤病，也不为康复、术后、妊娠、心血管疾病或其他需要医疗监督的情况自动制定训练。锐痛、关节痛、肿胀、胸痛、晕厥、异常气短或动作明显异常时停止常规算法。

## 训练配置

配置保存在现有 `减脂档案.md`，最小结构：

```markdown
## 训练配置
- 主要目标：减脂保肌/增肌/力量/心肺，按优先顺序
- 训练经验：未系统训练/初级/中级/高级
- 器械条件：无器械/居家哑铃或弹力带/健身房/其他
- 单次可用时长：范围或典型分钟数
- 可训练频率：范围，可写“不固定”
- 伤病与限制：无或具体部位
- 不喜欢动作：无或具体动作
```

初次一次询问全部缺失项。月初只问训练目标、可用时间范围、器械、伤病/疼痛是否变化；“没变化”即复用，不要求固定星期。

## 训练账本

`训练记录.csv` 一行一个动作，表头由脚本固定。`训练ID` 是一节训练的唯一键；同一训练的恢复反馈只保存在该训练第一行。饮食账本只保留摘要和 `[training:训练ID]`，不得复制动作级明细。

双写顺序：

1. 写训练动作并回读动作数、训练 ID 和字段。
2. 写饮食摘要并回读唯一标签。
3. 第二步失败返回 `partial`；用相同 ID 重试，只补摘要。
4. 两步都成功才说“已同步”。

## 动作输入

`record --exercises` 接收 JSON 数组，例如：

```json
[
  {"name":"深蹲","sets":3,"reps":"8","weight_kg":60,"rir":2},
  {"name":"卧推","sets":3,"reps":"8","weight_kg":40,"rir":2},
  {"name":"快走","minutes":20,"rpe":4}
]
```

脚本内置常见动作的主要/次要部位。未知动作会失败；只有明确映射后才添加 `primary`、`secondary`，值限胸、背、肩、肱二头、肱三头、核心、臀、股四头、腘绳肌、小腿。

## 达标判断

力量计划以完成组数、次数区间、动作质量和 RIR 为准：

- 达标：完成大部分计划组，进入次数区间，动作稳定，通常保留 2～4 次余力。
- 偏轻：稳定超过次数上限且余力仍多；下次只增加少量次数或重量之一。
- 偏重：多组达不到下限、频繁力竭或动作变形；下次减重量、组数或动作难度之一。
- 疼痛或异常：不做渐进建议，先停止相关动作。

有氧以时长与 RPE/谈话强度判断；设备热量只作备注。力量组数和有氧分钟不能互相换算。

若本次由 `plan` 生成，记录后运行 `evaluate --session-id ... --plan '...'`。脚本按计划动作、组数下限、次数区间和 RIR 区间输出达标/偏轻/偏重：总体至少 80% 动作达标才算达到主要目标。下次只改变重量、组数、次数或动作难度中的一个；疼痛会停止渐进建议。

## 恢复规则

脚本根据主要/次要部位、组数或时长、RIR/RPE、训练感受生成宽区间。区间表示“下一次重训复查窗口”，不是组织恢复完成时间：

- 轻刺激：约 24～36 小时后复查。
- 中刺激：约 36～60 小时后复查。
- 高刺激：约 48～72 小时后复查。
- 很高刺激、偏重或接近力竭：约 72～96 小时，偏重可加宽。

同一部位在上一个窗口结束前再次训练，新一轮上限延长一个保守档；不把小时线性相加，不输出小数百分比。反馈优先级：疼痛警示 > 明显影响动作 > 时间区间 > 轻微疲劳。连续至少 3 次“正常”才把个人窗口略缩短；至少 2/3 次“明显影响动作”才延长。单次异常不永久校准。

## 滚动训练队列

计划以“下一节”为单位，不绑定星期：

- 在最近 28 天力量训练中交替 A/B；自然周变化不重置。
- 本次可用 ≤30 分钟时最多 4 项，31～60 分钟最多 5 项，更长最多 6 项。
- 初级或频率不固定时优先全身动作，避免一次只练小肌群。
- 主要部位处于恢复/疼痛状态时跳过相关动作；可执行动作少于 3 项时改为低强度步行或休息。
- 用户临时多出一次时间时继续下一节，不提高后续必须完成的周频率。

## 部位图

`render` 默认生成自包含 HTML，内部使用原创矢量表面肌群图。正面必须写明“正面 · 前侧”，背面必须写明“背面 · 后侧”；肱二头、股四头等前侧肌群放在正面，肱三头、背、臀、腘绳肌等后侧肌群放在背面，肩、核心和小腿可按其前后表面同时显示。肌群名称须用引导线直接连接对应区域，不能只在图外给无位置关系的列表。

省略 `--output` 时固定覆盖系统临时目录中的 `diet-fat-loss-tracker/training-muscle-map.html`，不在健康项目、个人档案目录或当前工作目录留下图片。只有用户明确要求永久保存或导出时才传 `.html` 或 `.svg` 路径。

深浅色仅表示选定周期内的训练刺激，不能标成肌肉增长、热量消耗或恢复百分比。同样输入必须生成同样内容。解剖方向与主要表面肌群位置参考 [NIH/NCI SEER 解剖术语](https://training.seer.cancer.gov/anatomy/body/terminology.html)、[上肢肌群](https://training.seer.cancer.gov/anatomy/muscular/groups/upper.html)、[下肢肌群](https://training.seer.cancer.gov/anatomy/muscular/groups/lower.html)和 [OpenStax 肌肉系统概览](https://openstax.org/books/anatomy-and-physiology-2e/pages/11-2-naming-skeletal-muscles)；底图必须自行绘制，不复制第三方现成解剖图。

## 饮食联动

常规训练应在月度活动变化中复核，不能同时作为活动系数和每日额外消耗重复计算。只有明确超出日常计划的额外有氧，才沿用现役 100/200/300 千卡保守弹性；力量训练和设备显示热量不直接吃回。
